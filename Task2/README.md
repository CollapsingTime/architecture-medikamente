## Новые блоки Privacy by Design

Зелёные блоки на диаграмме - новые системы, которые закрывают проблемные зоны `Problem_areas.md` (R-xx):

| Блок | Что делает | Закрывает |
|---|---|---|
| IAM | Единый вход, MFA, роли (RBAC) и атрибуты (ABAC) доступа; пациент видит только свои данные | R-02, R-12 |
| Реестр согласий | Согласия и отзывы, запросы на удаление и прекращение обработки | R-06 |
| Токенизация и обезличивание | Токен пациента вместо ФИО для лаборатории и партнеров, псевдонимы и маски для выгрузок | R-08, R-14 |
| Управление ключами | Ключи шифрования хранятся отдельно от данных (Vault/KMS) | R-04 |
| Каталог данных | Теги и lineage полей, проверка релизов на работу с тегированными данными в CI/CD | R-01, R-07, R-11 |
| Аудит и мониторинг | Журнал доступа к ПДн, нетипичные действия, алерты ответственному за ПДн | R-05, R-15 |
| DLP | Запрет выноса медданных с рабочих мест, контроль почты и носителей | R-03, R-09 |

Внешний доступ к медицинской системе идет через API-шлюз, который отдает поля по политике и контрактам (R-08).

Медицинская система связана с каталогом данных (тегирование полей по таксономии) и DLP (контроль выноса данных C3 с рабочих мест).

## Аналитическая платформа

Отдельный слой аналитики (пунктиром на диаграмме - развитие после MVP, в контуре MVP его нет):

- данные приходят из медицинской системы уже псевдонимизированными, без ФИО и контактов;
- внутри - сырая и обработанная зоны Data Lake и витрины;
- BI, ML и LLM работают только с обезличенными данными на сервере (R-14);
- платформа пишет журнал доступа в аудит и обновляет теги и lineage в каталоге данных.

## Где разворачивается

Все системы - на серверах в Российской Федерации (152-ФЗ).
